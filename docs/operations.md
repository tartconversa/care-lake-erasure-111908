# 撤回清除与存续处理操作说明

本说明面向管理员，解释各入口的用途、状态口径与恢复语义。所有数据均为合成；保留规则是项目内约定，不对应现实法规推断。

## 布局

```
<运行目录>/
  lake/
    detail/        明细（人员、服务）
    derived/       派生（人员日表、去身份控制数）
    exports/       已交付但仍受管理的导出副本
    restricted/    结算保留凭据（独立范围与期限）
  state/
    state.db       受限运行日志：进度、墓碑、例外、交付与运行记录
    secret.key     键控散列密钥（600）
    verifications/ 核对记录（只含散列与位置，不含个人值）
```

清除范围由副本登记（血缘边 + 声明身份字段）与实际内容扫描决定，不按文件名猜测。共享文件只改写请求覆盖的行与字段，他人记录不动。

## 状态口径：仅限制访问 ≠ 已完成清除

- **仅限制访问**：请求已收到，新交付已被限制，但物理清除未完成（未开始或进行中）。此时湖内可能仍有旧值，不得以“查不到”冒充“已清除”。
- **已完成清除**：范围内全部副本（明细、派生表、受管导出）均已改写。若仍有生效中的保留例外，状态会标明“剩余例外待期履行”；例外全部履行后为“已了结”。

`status` 按请求给出处理范围、每个副本的处理结果、未完成位置（含原因，如“副本暂不可达”）、剩余例外（依据、覆盖字段、到期）与最近核对结果。

## 入口

```bash
python -m lakeops init --root 运行目录 --source data --now 时间
python -m lakeops withdraw --root 运行目录 --request-id E9 --person P4 --fields '*' [--partner B]
python -m lakeops purge --root 运行目录 [--request E1 | --all] --now 时间
python -m lakeops ingest --root 运行目录 [--delivery D1 | --file 投递.json] --now 时间
python -m lakeops deliver --root 运行目录 --delivery-id X1 --partner A --now 时间
python -m lakeops refer --root 运行目录 --delivery-id X1
python -m lakeops status --root 运行目录 [--request E1] [--json]
python -m lakeops verify --root 运行目录 --request E1 --now 时间
python -m lakeops drill --root 运行目录 --copy C3 --availability available
python -m lakeops grant --root 运行目录 --authority-id A9 --person P2 --partner B \
  --fields service_id,fee_fen --from-date 2026-11-15 --until-date 2026-12-01
```

`--now` 注入时钟（ISO 8601），缺省用真实当前时间；演练与复现请显式注入。`drill` 只用于演练副本可达性，不代表真实网络。

## 可恢复进度

- 每次清除先登记运行记录再开工；文件改写幂等，进度随事务提交。文件改写后进程中断，重跑会接着处理欠缺的副本，不会重复破坏仍有效人员的数据。
- 受管导出暂不可达时任务记为“暂不可达”，请求保持“仅限制访问”，绝不汇总成已完成；恢复可达后重跑同一命令即可续清。
- 保留期届满不清零了事：到期例外在下一次 `purge` 中继续执行原清除请求，凭据删除、例外标记已履行，请求才转为已了结。

## 保留例外与不可回连

- 整人清除不带走依法保留的结算凭据：凭据在改写明细前提取到独立的受限副本，只含依据覆盖的受限字段与期限，不含人员键。
- 例外必须能说明具体依据、覆盖字段与到期时间（`status` 的“剩余例外”）。
- 去身份控制数按合作方与月份保留，清除不回减；湖内文件不含可经内部编号、原件定位或关联表回连已清除身份的明文路径。运行态依据登记随清除与身份解绑；`state/` 是受限运行日志，通用查询接口不读取。
- 到期后凭据删除，控制数仍可保留。

## 后续资料接收

- 服务数据每天入湖、旧机构离线包撤回后补到，都走 `ingest`：已清除的整人身份、已清除的服务键、已清除的字段值一律不得重新出现（拒收或剔除，接收日志只记散列与字段名）。
- 重复投递幂等跳过；无有效处理依据（含依据空窗期）拒收。
- 撤回后重新建立的授权只放行其有效期窗口内的新服务数据；窗口外历史数据与已清除服务键不得借重授权复活。

## 交付与撤回互斥

- 收到撤回即限制新交付：交付按当时仍允许使用的完整数据构建（已撤回的行排除、字段置空）。
- 存在未完成的清除运行时，交付明确停止并记录原因；不会留下“明细已清除但衍生名单仍可下载”的中间态。
- 每次交付登记为受管副本并纳入后续清除范围。`refer` 查看历史交付时，只显示内容已清除的范围与合法保留说明，不返回旧个人资料。

## 核对

`verify` 用键控散列在实际文件上扫描请求范围内的已清除值：残留逐处列出（副本、路径、JSON 位置、字段），生效例外覆盖的凭据计为“例外内保留”而非残留。核对记录只含散列、路径与字段名，不保存待清除的个人值。
